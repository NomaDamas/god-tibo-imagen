# 아스터 아카데미 400종 몬스터 컷아웃 시스템 설계

## 목표

선택한 1번 전투 화면의 밝고 단순한 아카데미 SF 미감을 유지하면서, 방치형 전투에 사용할 몬스터 400종을 실제 제작 가능한 구조로 만든다. 특정 상용 게임의 캐릭터·로고·학교·유니폼·무기·UI 배치를 복제하지 않고, 흰색·차콜·시안 기반의 독창적인 아스터 아카데미 세계로 구성한다.

## 선택한 제작 방식

세 가지 방식 중 첫 번째를 사용한다.

1. **단일 투명 컷아웃 + 공용 모션 프로필 — 채택.** 몬스터마다 투명 PNG 한 장을 만들고 대기·이동·공격·피격·사망은 코드 모션으로 처리한다. 400종 생산과 모바일 메모리 관리가 가능하다.
2. 파츠 분리 퍼펫. 표현력은 높지만 몬스터마다 4~8개 파츠와 리깅 정보가 필요해 첫 400종 범위에는 과하다. 구역 보스의 2차 고도화에만 사용한다.
3. 프레임 애니메이션 아틀라스. 품질 상한은 높지만 9,600프레임 이상이 필요하고 생성 일관성 검수가 어렵다. 현재 범위에서는 사용하지 않는다.

## 세계관

아스터 아카데미 도시는 학생 훈련과 도시 관리를 위해 `ASTER GRID`라는 거대한 실습망을 사용한다. 방치 전투 중 출현하는 몬스터는 생물이 아니라, 훈련 데이터·관리 장비·도시의 감정 기록이 뒤섞여 만들어진 **오류체**다. 오류체를 정화하면 실습망에 다시 흡수되며, 더 강한 형태로 재학습되어 돌아온다.

등급은 네 단계다.

| 등급 | 코드 | 외형 규칙 | 크기 배율 |
|---|---|---|---:|
| 기초형 | `basic` | 원형의 가장 단순한 실루엣 | 1.00 |
| 강화형 | `advanced` | 방호판·센서·도구 중 2개 추가 | 1.10 |
| 오류형 | `glitched` | 비대칭 파츠·과부하 코어·분리 부품 중 2개 추가 | 1.18 |
| 초월형 | `overdrive` | 지휘 안테나·부유 링·대형 코어 중 2개 추가 | 1.30 |

색만 바꾸는 변종은 금지한다. 같은 원형의 등급 변화는 핵심 실루엣을 유지하면서 매 단계 최소 두 개의 구조적 변화가 있어야 한다.

## 이미지 계약

- 파일 형식: 실제 알파 채널을 가진 PNG
- 생성 기준 캔버스: 정사각형, 최소 768×768
- 카메라: 전신 3/4 쿼터뷰, 화면 왼쪽을 바라봄
- 기준선: 발 또는 최하단 부유점이 캔버스 높이 88% 부근
- 점유율: 비투명 바운딩 박스가 캔버스 너비와 높이의 45~82%
- 스타일: 단순하고 둥근 치비 비율, 큰 형태 3~5개, 작은 장식 최소화
- 재질: 흰색 무광 장갑, 차콜 관절, 구역 강조색 발광부
- 금지: 배경, 바닥, 그림자, 텍스트, 숫자, 로고, 액자, 복잡한 문양, 가는 장식 다발

## 모션 계약

각 몬스터는 PNG 한 장과 `motionProfile` 하나를 가진다.

| 프로필 | 대상 | 대기 | 이동 | 공격 |
|---|---|---|---|---|
| `bob` | 소형 마스코트 | 짧은 상하 호흡 | 통통 튀기 | 빠른 앞찍기 |
| `runner` | 사족형 | 몸통 기울기 | 좌우 보폭 흔들기 | 짧은 돌진 |
| `hover` | 비행형 | 부유 사인파 | 부드러운 활주 | 뒤로 당긴 뒤 발사 |
| `caster` | 인간형 | 코어 맥동 | 잔걸음 | 충전 후 반동 |
| `heavy` | 중장형 | 느린 중량 이동 | 낮은 진폭 흔들기 | 큰 준비 동작과 내려치기 |

피격은 공통으로 90ms 좌우 흔들기와 백색 플래시, 사망은 420ms 뒤로 기울기·축소·페이드로 처리한다. `prefers-reduced-motion`에서는 모든 반복 모션을 중지한다.

## 데이터 계약

`monster-archetypes.json`은 100개 원형의 정본이다. 각 항목은 다음 필드를 가진다.

- `zoneId`, `zoneSlug`, `zoneName`
- `archetypeId`, `slug`, `name`, `role`
- `identity`, `palette`, `motionProfile`

빌드 스크립트가 네 등급을 확장해 `monster-catalog.json` 400개 항목을 만든다. 생성 항목은 `id`, `tier`, `tierName`, `scale`, `asset`, `structuralChanges`를 추가로 가진다.

## 첫 검증 배치

구역 01 중앙 광장의 처음 세 원형을 네 등급씩 제작한다.

1. 안내구슬 `guide-orb` — 소형 안내 로봇, `bob`
2. 배너하운드 `banner-hound` — 접이식 안내판과 결합된 사족형, `runner`
3. 순찰카이트 `patrol-kite` — 얇은 날개와 카메라 코어를 가진 비행형, `hover`

총 12 PNG다. 이 묶음이 통과하기 전에는 나머지 388종의 이미지 생성을 시작하지 않는다.

## 화면 검증 도구

기존 전투 프로토타입에 `MONSTER LAB` 전환 버튼을 추가한다. 랩에서는 제작이 끝난 원형을 계열 탭으로 고르고 네 등급을 비교하며, 하나를 선택해 대기·이동·공격·피격·사망 상태를 직접 재생한다. 실제 제작 범위는 `monster-production.json`을 정본으로 삼아 에셋 검증기와 UI가 함께 확장된다. 이미지와 모션을 분리해 교체 가능한지 확인하는 것이 목적이다.

## 완료 조건

- 20구역·100원형·4등급의 카탈로그가 정확히 400개이며 ID와 에셋 경로가 중복되지 않는다.
- 첫 12 PNG가 RGBA, 투명 모서리, 점유율 계약을 통과한다.
- 같은 원형의 네 등급이 같은 종으로 읽히고 단계별 구조 변화가 두 개 이상이다.
- 몬스터 랩에서 다섯 동작이 재생되며 일시정지와 배속에 반응한다.
- `npm run verify:monsters`와 `npm run build`가 통과한다.

## 가드레일

- 첫 배치: 12 PNG
- 이미지별 교정: 최대 2회
- 투명화가 두 번 실패하면 해당 이미지만 중단하고 원인을 기록한다.
- 상용 게임 고유 캐릭터나 UI를 닮은 결과는 폐기한다.
